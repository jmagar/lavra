# Design a feature

Inspect the repository and its `AGENTS.md`, then identify the affected product behavior, architecture, dependencies, and acceptance criteria. Use installed skills under `.agents/skills/` when their descriptions match the task. Ask focused Codex specialist subagents for independent research or architecture review only when bounded parallel work helps. Ground technical claims in source code and current documentation.

Write a concise design with the user-visible behavior, affected modules, data flow, failure cases, testing approach, and open decisions. Create an epic and child beads with dependencies if the user requested implementation tracking. Preserve the distinction between an approved design and completed implementation.
